# 店铺采集

只负责采集、保存、核验采集结果及查询执行进度。复用本机固定程序，正常流程不逐商品调用模型，不做选品分析或预测。

## 明确采集目标

- **采集目标与当前分析店铺独立。** 用户明确指定另一家店时，以该目标为准，不用当前页面、浏览器标签、对话历史或店铺排列顺序代替目标。
- 用户必须明确给出完整店铺名称、准确编号或店铺链接。未填写的模板、空目标、“其他店铺”“当前店铺”或顺序简称均不作为唯一目标；先简短询问准确店名，不启动任务。
- 用 `shops` 的本机已采集店铺目录核对完整名称或编号；同名、多目标、名称不完整或链接未核实都先确认，不模糊匹配。用户链接对应未登记目标时按原项目的登记与身份核验流程处理；不能把新链接绑定到当前分析店铺。
- 明确名称和编号同时出现时必须指向同一店；冲突则停止并询问。提问中仅提供店名时先解析准确编号，再始终携带此编号。
- 从任务、网页来源、封存快照、发布收据到商品、图片、SKU及每日记录，店铺身份必须一致。不一致立即停止，不写入其他店、不换成当前店继续，也不合并不同店数据。

## 固定程序入口

- 项目路径由环境变量 `PDD_COLLECT_PROJECT` 指定；仓库内使用时默认采用此 Skill 所属仓库根目录，服务 `http://127.0.0.1:8878`。
- 使用项目 Python 执行本 Skill 的 `scripts/collect.py`，转调项目 `scripts/collection_skill.py` 和原后台采集入口，不复制爬虫实现。
- 以下 `<完整店名或编号>` 需先替换为已经唯一核实的目标；不得原样提交占位符。

| 操作 | 参数 |
|---|---|
| 列出可采集店铺 | `shops` |
| 采集指定店铺 | `start --shop "<完整店名或编号>"` |
| 查询该店采集状态 | `status --shop "<完整店名或编号>"` |
| 查询指定任务 | `status --shop "<完整店名或编号>" --job collect_…` |
| 用户明确要求批量补采该店有销量商品SKU | `start --shop "<完整店名或编号>" --kind sku_batch` |
| 查询该店SKU进度 | `status --shop "<完整店名或编号>" --kind sku_batch` |
| 有界等待本店任务 | `wait --shop "<完整店名或编号>" --job collect_… --seconds 25` |
| 用户明确要求停止该任务 | `cancel --shop "<完整店名或编号>" --job collect_…` |

用户要求采集店铺只授权该店商品与主图任务，不包含SKU。单品SKU由用户在所选商品的“查看SKU”弹窗点击“采集SKU／重新采集SKU”发起；本桥接没有单品参数，不用`sku_batch`代替单品请求。只有用户明确要求批量采集或补采该店SKU时，才使用`--kind sku_batch`；“采集店铺”“更新数据”、打开SKU表或查询进度均不能推定此授权。

启动前检查目标店是否已有运行任务，已有则查询原任务，不重复提交。请求结果未确认时先查目标店状态，不立即重试。不自动续跑历史SKU批次、旧队列或全店后续指令，也不删除旧收据。保留任务编号，不逐商品操作浏览器或反复读取长日志，每次等待不超过45秒。

## 采集与保存

全店上新列表扫描并确认结束边界 → 检查及补齐主图 → 配对备份、副本验收 → 保存目标店数据并更新数据舱 → 结束该任务。全店采集不生成或执行自动SKU队列。

按需SKU仍限定精确已拼/已抢件数大于0的原卡，0、模糊或缺失销量保留商品记录但不进入SKU读取范围。单品使用仅追加SKU存档的保存保护，不写业务双库；显式批量仍使用原配对备份协议。具体身份、图片校验、保存与失败边界见项目`docs/SKU_CAPTURE.md`。

SKU定位由程序执行本店搜索、完整标题/主图/实时销量核对、加号读取和关闭返回，不逐页扫描全店或逐规格调用模型。搜索结果编号不替代原店铺或原卡编号；身份歧义、关闭或返回失败时保留部分并暂停，不能绕过核对继续。

只更新目标店当天的有效展示，保留此前日期和原始快照。按本次请求范围报告：全店商品及主图全部验收发布后可称该全店任务完成，不因未请求SKU而报未完成，也不能声称全部SKU已采。主图缺失或明确请求的SKU未完成则分别报告。未明确提供的价格、图片及商品ID保持未知，不借用其他店或其他商品数据。发布数据舱不意味着把采集目标改成当前分析选择，也不自动切换用户的分析店铺。

仅复用用户普通Google Chrome原登录会话，不启动Edge、另建配置或导出Cookie/TOKEN。登录、连接授权及验证码由用户完成。登录失效、来源不符、身份歧义、限制或未知异常时保留已保存证据并报告，不无限刷新、不删锁、不换店继续。服务未运行时恢复原服务，不创建替代空库。

## 快捷使用与结果

自然语言例式：“采集店铺：<完整店铺名称>”“查看<完整店铺名称>采集进度”。网页“复制 Skill 指令”提供待填写模板，粘贴到Codex后先补全目标；网页“采集当前店铺”是另一个明确绑定页面选择的程序按钮，不能替代用户在对话中指定的另一家店。网页查询Agent本身不加载个人Skill。

仅简短汇报准确目标店名、本次任务状态、商品数量、主图缺项；仅在本次明确请求SKU时报告对应进度。不要输出凭据或整店长日志。本仓库不含本机验收收据；旧自动联采策略已被按需策略替代，旧成功与失败证据保留，代码测试不能当真实采集完成。
